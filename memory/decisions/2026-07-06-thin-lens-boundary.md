# 맥락/도구 경계 — "얇은 렌즈 + 정본은 현장"

**결정**: 루트 매니저는 **얇은 고고도 렌즈**로 확정. 하위 레포 맥락을 미러링·연속 sync하지 않는다.

1. **스킬·훅은 제자리** — 프로젝트 전용 도구(블로그의 `write-blog-post`·`deploy-bumang`·`segment-draft`)는 해당 레포 `.claude/`에. 루트로 옮기거나 링킹하지 않음. 판정 기준 = **"프로젝트 내부냐 가로지르냐"**(내부→그 레포, 가로지름→루트).
2. **작업은 도구가 사는 곳에서** — 프로젝트 내부 작업은 하위 세션(스킬·훅이 cwd-scoped라 거기서만 발화), 커밋/푸시 오케스트레이션·상담은 루트.
3. **decision 두 집** — 포트폴리오 결정은 루트가 직접 씀(`memory/decisions/`), 프로젝트 결정은 하위 레포에(→ 2026-07-11에 `PLANNING.md`로 구체화됨, [[2026-07-11-planning-first]]).
4. **루트는 on-demand로 읽는다** — git 로그 + 하위 `CLAUDE.md`를 상담 시 즉석 생성. 저장(미러)하지 않음.
5. **자동화는 필요 증명 후** — `/wrap` 증류 스킬·`/portfolio-brief` 다이제스트는 보류. **"하위에서 정했는데 루트가 몰랐네" 순간이 3번+ 쌓이면** 그때 제작(그 3번이 무엇을 담을지 알려준다).
6. **캡처 정본 하나** — bespoke `memory/`로 통일. workbook(`wb-knowledge`/`wb-session`)을 개인 레포에 겹쳐 쓰지 않음(정본 이중화 = 최대 손실 위험).

**이유**:
- (a) **"손실없이 raw 축적"은 틀린 목표** — 가치는 증류물(결정·이유·함정)이지 과정 스트림이 아님.
- (b) 매니저가 얇은 건 정상; 문제는 얇음이 아니라 *결정*이 새는지 여부.
- (c) Claude Code 스킬·훅은 **cwd-scoped**라 루트에서 하위 도구를 온전히 못 씀 → 작업축과 맥락축을 분리하면 해소.
- (d) 지금 상시 캡처를 지으면 무엇을 담을지 모른 채 그릇부터 만드는 셈(YAGNI). 본진은 개미지표·타로·블로그, 인프라는 본진이 아플 때만.

**상태**: 확정 · 인프라 동결.
