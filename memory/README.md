# 비서의 뇌 (memory/)

여기는 **포트폴리오 매니저 비서의 장기기억**이다. `CLAUDE.md`(프로토콜)·`PROJECTS.md`(스냅샷)와 함께 이 루트에서 일하는 나(Claude)의 총체적 의사결정 기록을 담는다.

**보인다. 안 휘발된다.** 이건 채팅 컨텍스트가 아니라 디스크 위의 마크다운 파일이다. 세션이 끝나도, 컨텍스트가 압축돼도, 맥을 껐다 켜도 그대로 남는다. 사라지는 유일한 경우는 네가 파일을 지울 때뿐.

## 무엇을 기억하고, 무엇을 기억하지 않는가

기억을 성질별로 갈라서 **재생성 불가한 것만** 저장한다:

| 성질 | 예시 | 여기 저장? |
|---|---|---|
| 재생성 가능 | 레포 파일 트리, 커밋 모멘텀 | ❌ 필요할 때 git으로 즉석 생성 |
| 천천히 변함 | 아키텍처 지도(핵심 디렉토리·엔트리포인트) | 🔶 `architecture/`에 온디맨드 |
| **재생성 불가** | **의사결정·이유·이탈·유저 성향** | ✅ 여기가 핵심 |

레포 구조가 궁금하면 `git ls-files`로 뽑으면 된다 — 그건 기억할 게 아니라 **왜 그렇게 만들었는지(결정)**를 기억한다.

## 구조

```
memory/
├── README.md            ← 이 파일
├── preferences.md       ← 유저 성향 · 매니저 행동 규칙
├── decisions/
│   ├── README.md        ← ⭐ 의사결정 인덱스 — 세션에서 항상 읽는 건 이것뿐
│   ├── YYYY-MM-DD-<slug>.md   1결정 1파일 (본문은 필요할 때만)
│   ├── {ant-index,zentarot,bumang-blog}.md   프로젝트 포인터 (정본은 각 repo PLANNING.md)
│   └── archive/         ← 강등된 옛 결정 (인덱스 300줄 초과 시 생김)
└── architecture/        ← 레포별 아키텍처 지도 (필요할 때 생김)
```

## 로드 규약 — 총량과 상시 로드량을 분리한다

기억의 양이 늘어도 **매 세션 읽는 양은 늘지 않아야 한다.** 그래서:

- 세션에서 **항상 읽는 건 `decisions/README.md` 인덱스뿐**이다. 결정 본문은 필요할 때 그 파일만 연다.
- 인덱스 한 줄에 **결론과 핵심 함정**까지 담는다 — 본문을 안 열고도 판단할 수 있어야 한다.
- 찾을 땐 `grep -r <키워드> memory/decisions/`.
- 인덱스가 **300줄**을 넘으면 오래된 확정 결정을 `archive/`로 강등하고 인덱스엔 `"N건 — grep으로 조회"` 한 줄로 접는다. → 상시 로드분이 **상수로 고정**된다.

> **압축(요약)은 하지 않는다.** 요약은 이 시스템이 지키려는 바로 그것(이유·함정 디테일)부터 버린다. 크기 문제는 계층화로 푼다. 근거: [[decisions/2026-07-26-memory-sharding]].

## 규칙

- **한 결정 = 한 파일.** `decisions/YYYY-MM-DD-<slug>.md` + 인덱스 한 줄. 기존 파일에 append하지 않는다(그게 monolith로 돌아가는 길).
- **결정엔 반드시 이유를 붙인다.** 나중의 나/너가 "왜 이렇게 갔지"를 되물을 때 답이 여기 있어야 한다.
- 결정이 바뀌면 파일을 지우지 말고 frontmatter `status`를 갱신(`확정`→`폐기`)하고 새 파일에서 `[[이전결정]]`으로 연결.
- 반복되는 결정이 규칙으로 굳으면 `CLAUDE.md`로 **승격**하고 로그엔 포인터만 남긴다(정본 이중화 금지).
- 결정끼리 연결은 `[[파일명]]`으로 (예: `[[zentarot]]`).
- 프로토콜 전문은 루트 `CLAUDE.md`의 **"비서 프로토콜"** 섹션 참조.
